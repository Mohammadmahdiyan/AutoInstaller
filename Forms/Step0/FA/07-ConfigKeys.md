# کلیدهای پیکربندی (Configuration Keys)

این مرجع، کلیدهایی را توضیح می‌دهد که Parser و Installer فعلی آن‌ها را می‌خوانند.

کلیدهای مربوط به Manifest پکیج باید در سطح بالای یک آبجکت JSON قرار بگیرند.

Manifest در ریشه پکیج با اولویت زیر جستجو می‌شود:

1. `mod.json`
2. `config.json`
3. `<نام پوشه پکیج>.json`

تشخیص نام فایل نسبت به حروف بزرگ و کوچک حساس نیست.

ویژگی `type` و کلیدهای `InstallFile(s)`، `InstallFolder(s)`، `IgnoreFile(s)` و `IgnoreFolder(s)` نسبت به حروف بزرگ و کوچک حساس نیستند.

سایر کلیدهای Manifest که در ادامه آمده‌اند، در حال حاضر باید دقیقاً با همان شکل camel-case نوشته شوند.

چهار گروه کلیدهای Install/Ignore می‌توانند یک رشته یا آرایه‌ای از رشته‌ها را دریافت کنند. شکل مفرد و جمع این کلیدها با یکدیگر ترکیب می‌شوند.

---

## `type`

برای یک Manifest غیرخالی، این کلید باید یک مقدار رشته‌ای (`string`) داشته باشد.

این کلید رفتار نصب را طبق توضیحات `06-ConfigTypes.md` تعیین می‌کند.

تشخیص مقدار `type` نسبت به حروف بزرگ و کوچک حساس نیست و فاصله‌ها، خط تیره‌ها (`-`) و زیرخط‌ها (`_`) نیز نادیده گرفته می‌شوند.

```json
{
  "Type": "PutInCleo"
}
````

---

## `require` و `requires`

کلید `require` یک آبجکت Requirement را می‌پذیرد.

کلید `requires` می‌تواند یک آبجکت یا آرایه‌ای از آبجکت‌ها را دریافت کند.

اگر هر دو کلید وجود داشته باشند، هر دو بررسی می‌شوند.

فیلدهای پشتیبانی‌شده:

* `checkFile`: مسیر یک فایل. می‌تواند یک رشته یا آرایه باشد. اگر آرایه باشد، اولین رشته غیرخالی استفاده می‌شود.
* `checkFolder`: مسیر یک پوشه. می‌تواند یک رشته یا آرایه باشد. اگر آرایه باشد، اولین رشته غیرخالی استفاده می‌شود.
* `checkFiles`: یک رشته یا آرایه‌ای از مسیر فایل‌ها. برای موفق بودن شرط فایل، تمام فایل‌های مشخص‌شده باید وجود داشته باشند.
* `checkFolders`: یک رشته یا آرایه‌ای از مسیر پوشه‌ها. برای موفق بودن شرط پوشه، تمام پوشه‌های مشخص‌شده باید وجود داشته باشند.
* `reqAddress`: آدرس پکیجی که برای برطرف کردن یک Requirement مفقود استفاده می‌شود.
* `reqPath`: نام مستعار `reqAddress` است و فقط زمانی استفاده می‌شود که `reqAddress` تعیین نشده باشد.
* `require`: یک آبجکت Requirement تو‌در‌تو. فیلدهای داخل آن فقط مقادیری را تکمیل می‌کنند که در آبجکت بیرونی قبلاً تعیین نشده باشند.

مسیرهای نسبی برای بررسی، از پوشه بازی محاسبه می‌شوند.

مسیرهای Absolute/Rooted مستقیماً بررسی می‌شوند.

یک Requirement زمانی موفق محسوب می‌شود که **شرط کامل فایل یا شرط کامل پوشه** برقرار باشد.

اگر Requirement برقرار نباشد، Installer از `reqAddress` برای پیدا کردن و نصب پکیج موردنیاز استفاده می‌کند.

اگر `reqAddress` وجود نداشته باشد، نصب با نمایش یک هشدار متوقف می‌شود.

```json
{
  "type": "PutInModLoader",
  "require": {
    "checkFile": "cleo.asi",
    "reqAddress": "Scripts/CLEO"
  },
  "requires": [
    {
      "checkFolders": ["cleo", "modloader"]
    },
    {
      "checkFiles": ["modloader.asi", "cleo.asi"]
    }
  ]
}
```

نام این Propertyها در Parser فعلی نسبت به حروف بزرگ و کوچک **حساس است**؛ بنابراین باید دقیقاً با همین املا استفاده شوند.

## `conflictCleanup`

Parser یک آبجکت `conflictCleanup` را می‌خواند و ذخیره می‌کند.

این آبجکت شامل فیلدهای زیر است:

* `file`، `folder`: یک مسیر. می‌تواند یک رشته یا آرایه باشد. اگر آرایه باشد، اولین مقدار غیرخالی استفاده می‌شود.
* `files`، `folders`: یک رشته یا آرایه‌ای از مسیرها.
* `replaceWith`: یک مسیر. می‌تواند یک رشته یا آرایه باشد و در صورت آرایه بودن، اولین مقدار غیرخالی استفاده می‌شود.
* `replacesWith`: یک رشته یا آرایه‌ای از مسیرهای جایگزینی.

در حال حاضر، مسیرهای نصب موجود این آبجکت Cleanup را **به‌صورت خودکار اجرا نمی‌کنند**.

بنابراین وجود `conflictCleanup` در Manifest در حال حاضر باعث حذف فایل‌ها یا انجام عملیات جایگزینی نمی‌شود.

```json
{
  "type": "PutInModLoader",
  "conflictCleanup": {
    "files": ["old_mod.cs", "old_settings.ini"],
    "folders": "old_data",
    "replacesWith": ["new_mod.cs"]
  }
}
```

نام کلیدهای داخل این آبجکت در Parser فعلی نسبت به حروف بزرگ و کوچک **حساس است**.

---

## `deleteThis`

این کلید می‌تواند یک رشته یا آرایه‌ای از مسیر فایل‌ها و پوشه‌ها را دریافت کند.

قبل از اجرای فرآیندهای نصب پشتیبانی‌شده، هر مسیر نسبت به پوشه بازی محاسبه می‌شود و اگر وجود داشته باشد حذف می‌گردد.

اگر مسیر مربوط به یک پوشه باشد، آن پوشه به‌صورت بازگشتی همراه با تمام محتویاتش حذف می‌شود.

مسیرهای Rooted و همچنین مسیرهایی که از محدوده پوشه بازی خارج شوند، رد می‌شوند.

```json
{
  "type": "PutInModLoader",
  "deleteThis": [
    "data/old_handling.cfg",
    "old_mod_folder"
  ]
}
```

نام دقیق کلید `deleteThis` الزامی است.

## `replacements`

این کلید برای نوع `PutAndReplace` استفاده می‌شود.

Validator وجود یک آرایه را الزامی می‌داند.

هر آیتم آرایه می‌تواند یکی از موارد زیر باشد:

* یک رشته مسیر که هم به‌عنوان Source و هم Destination استفاده می‌شود.
* یک آبجکت دارای فیلدهای رشته‌ای `source` و `target`.

مسیر `source` نسبت به Payload نصب محاسبه می‌شود.

مسیر `target` نسبت به پوشه بازی محاسبه می‌شود.

فایل‌های مقصد موجود از فرآیند Backup مربوط به جایگزینی استفاده می‌کنند.

```json
{
  "type": "PutAndReplace",
  "replacements": [
    "data/handling.cfg",
    {
      "source": "custom/weapon.dat",
      "target": "data/weapon.dat"
    }
  ]
}
```

خود کلید `replacements` و همچنین فیلدهای `source` و `target` در Parser فعلی نسبت به حروف بزرگ و کوچک **حساس هستند**.

---

## `InstallFile` و `InstallFiles`

هرکدام از این کلیدها می‌توانند یک رشته یا آرایه‌ای از رشته‌ها را دریافت کنند.

اگر هر دو کلید وجود داشته باشند، مقادیر آن‌ها با یکدیگر ترکیب می‌شوند.

سپس مقادیر:

1. `Trim` می‌شوند.
2. جداکننده مسیر آن‌ها به `\` استاندارد می‌شود.
3. موارد تکراری با نادیده گرفتن حروف بزرگ و کوچک حذف می‌شوند.

مسیرها باید نسبت به ریشه پکیج باشند و نباید از ریشه پکیج خارج شوند.

در `PutInCleo`، وجود هرکدام از این کلیدها حالت **File Whitelist** را فعال می‌کند.

یعنی هر فایل فهرست‌شده باید وجود داشته باشد.

اگر فایلی از یک زیرپوشه انتخاب شده باشد، هنگام نصب در `<game>\cleo` فقط نام فایل آن استفاده می‌شود و ساختار پوشه آن حفظ نمی‌شود.

```json
{
  "type": "PutInCleo",
  "InstallFile": "RZL Trainer.cs",
  "INSTALLFILES": [
    "logs/memory2026.cs",
    "RZL Trainer.cs"
  ]
}
```

---

## `InstallFolder` و `InstallFolders`

هرکدام از این کلیدها می‌توانند یک رشته یا آرایه‌ای از رشته‌ها را دریافت کنند.

مقادیر شکل مفرد و جمع با یکدیگر ترکیب شده و موارد تکراری حذف می‌شوند.

پوشه‌های مشخص‌شده باید وجود داشته باشند و در محدوده ریشه پکیج باقی بمانند.

در `PutInCleo`، محتویات این پوشه‌ها به‌صورت بازگشتی انتخاب می‌شوند و نام پوشه‌ها و ساختار داخلی آن‌ها در مسیر زیر حفظ می‌شود:

```text
<game>\cleo
```

```json
{
  "type": "PutInCleo",
  "InstallFolders": [
    "RZL Trainer",
    "scripts/helpers"
  ]
}
```

---

## `IgnoreFile` و `IgnoreFiles`

هرکدام از این کلیدها می‌توانند یک رشته یا آرایه‌ای از رشته‌ها را دریافت کنند و مقادیر هر دو شکل با یکدیگر ترکیب می‌شوند.

اگر مقدار بدون جداکننده مسیر باشد، آن نام فایل را در **هر سطحی از پکیج** پیدا کند، نادیده می‌گیرد.

اگر مقدار دارای جداکننده مسیر باشد، فقط همان مسیر دقیق نسبت به ریشه پکیج را نادیده می‌گیرد.

تشخیص نام فایل نسبت به حروف بزرگ و کوچک حساس نیست.

قوانین Ignore **بعد از مرحله انتخاب فایل‌های Install** اعمال می‌شوند.

```json
{
  "type": "PutInCleo",
  "IgnoreFile": "crash.log",
  "IgnoreFiles": [
    "logs/debug.txt",
    "temporary.ini"
  ]
}
```

---

## `IgnoreFolder` و `IgnoreFolders`

هرکدام از این کلیدها می‌توانند یک رشته یا آرایه‌ای از رشته‌ها را دریافت کنند و مقادیر هر دو شکل با یکدیگر ترکیب می‌شوند.

پوشه مشخص‌شده و تمام محتویات و زیرپوشه‌های آن، بدون توجه به حروف بزرگ و کوچک، از انتخاب خارج می‌شوند.

در `PutInCleo`، اگر `InstallFolders` وجود نداشته باشد اما `IgnoreFolders` وجود داشته باشد، تمام پوشه‌های سطح اول به‌صورت بازگشتی انتخاب می‌شوند؛ به‌جز پوشه‌هایی که در `IgnoreFolders` قرار دارند.

اگر نه `InstallFolders` وجود داشته باشد و نه `IgnoreFolders`، زیرپوشه‌ها به‌صورت خودکار انتخاب نمی‌شوند.

پوشه‌های زیر از انتخاب خودکار مستثنی هستند:

```text
.git
.vscode
.vs
```

اما اگر یکی از آن‌ها به‌صورت صریح در `InstallFolders` قرار داده شود، قابل نصب خواهد بود.

```json
{
  "type": "PutInCleo",
  "IgnoreFolders": [
    "logs",
    "RZL Trainer/cache"
  ]
}
```

## پیش‌فرض‌ها و موارد مستثنی در انتخاب فایل‌های CLEO

در `PutInCleo`، اگر `InstallFiles` وجود نداشته باشد، فایل‌های موجود در ریشه پکیج انتخاب می‌شوند.

زیرپوشه‌ها انتخاب نمی‌شوند، مگر اینکه یکی از شرایط زیر برقرار باشد:

* `InstallFolders` ارائه شده باشد.
* `IgnoreFolders` وجود داشته باشد و باعث فعال شدن انتخاب خودکار پوشه‌های سطح اول شود.

قوانین Ignore بعد از مرحله انتخاب اعمال می‌شوند.

Manifest نهایی‌شده، فایل‌های README و فایل‌های رسانه‌ای از لیست فایل‌های قابل نصب حذف می‌شوند.

سایر فایل‌های `.json` به‌صورت خودکار به‌عنوان Manifest در نظر گرفته نمی‌شوند.

```json
{
  "type": "PutInCleo",
  "InstallFiles": [
    "RZL Trainer.cs",
    "memory2026.cs"
  ],
  "IgnoreFiles": [
    "memory2026.cs"
  ]
}
```

در این مثال، `RZL Trainer.cs` نصب می‌شود اما `memory2026.cs` به دلیل وجود در `IgnoreFiles` حذف می‌شود.

## `config.json` مربوط به Dependencyهای داخلی

Manifest مربوط به Dependency موجود در:

```text
Scripts/A1-MyReqFiles
```

از یک Reader جداگانه استفاده می‌کند.

بنابراین Schema آن با Schema معمول انتخاب فایل‌های Install/Ignore یکسان نیست.

مقدار `type` در این Reader نسبت به حروف بزرگ و کوچک حساس نیست.

اگر مقدار `type` برابر با:

```text
PutInGameFolder
```

یا:

```text
PGF
```

باشد، پوشه `Essentials` در صورت وجود کپی می‌شود؛ در غیر این صورت، ریشه Dependency کپی خواهد شد.

Manifestهای Dependency دیگر می‌توانند Entryهای خود را به شکل‌های زیر ارائه کنند:

### آرایه‌ای از آبجکت‌ها در ریشه

آبجکت‌ها می‌توانند دارای یکی از این کلیدهای Source باشند:

* `source`
* `from`
* `path`
* `file`
* `folder`

مقصد نیز می‌تواند با یکی از این کلیدها مشخص شود:

* `destination`
* `target`
* `to`
* `installPath`

اگر مقصد مشخص نشده باشد، مقصد برابر با Source در نظر گرفته می‌شود.

### آبجکت‌های `files`، `folders` یا `directories`

این آبجکت‌ها مسیرهای Source را به رشته‌های Destination نگاشت می‌کنند.

### آرایه‌های `install`، `entries` یا `items`

این آرایه‌ها نیز از همان ساختار آبجکت بالا استفاده می‌کنند.

### سایر Propertyهای رشته‌ای در سطح ریشه

سایر Propertyهای رشته‌ای در ریشه به‌عنوان جفت‌های:

```text
source path : destination path
```

تفسیر می‌شوند.

کلیدهای مربوط به Entryهای Dependency در Reader فعلی نسبت به حروف بزرگ و کوچک **حساس هستند**؛ تنها استثنا `type` است.

```json
{
  "type": "PutInGameFolder",
  "install": [
    {
      "source": "Essentials/modloader.asi",
      "destination": "modloader.asi"
    },
    {
      "from": "Essentials/cleo.asi",
      "to": "cleo.asi"
    }
  ]
}
```

# مواردی که در حال حاضر پشتیبانی نمی‌شوند

مدل و Parser مربوط به Manifest، کلیدهایی برای انتخاب فایل‌های Backup تعریف نکرده‌اند.

بنابراین روی کلیدهایی مانند موارد زیر برای تغییر رفتار Backup حساب نکنید:

```text
backup
backupFiles
backupFile
backupFolders
backupFolder
dontBackupFiles
dontBackupFile
dontBackupFolders
dontBackupFolder
```

این کلیدها در حال حاضر رفتار Backup را تغییر نمی‌دهند.
