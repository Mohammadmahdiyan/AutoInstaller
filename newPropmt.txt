# پرامپت برای GitHub Copilot (Agent/Chat mode در VS Code)

این پروژه یه اپ WinForms به C# (.NET 8) برای نصب خودکار مادهای GTA San Andreas هست
(namespace: GtaSaModManager). من کد رو خط‌به‌خط بررسی کردم و باگ‌های زیر رو با دقت پیدا
کردم. لطفاً هرکدوم رو دقیقاً طبق توضیح فیکس کن، بعد کل سولوشن رو یه بار دیگه اسکن کن که
مورد مشابه دیگه‌ای جا نمونده باشه.

## باگ ۱ — اعتبارسنجی mod.json برعکس عمل می‌کنه
فایل: Forms/MainForm.cs، تابع InstallSelectedModAsync، حدود خط 2005
```csharp
if (jsonDoc.RootElement.ValueKind != System.Text.Json.JsonValueKind.Object || jsonDoc.RootElement.EnumerateObject().Any())
```
شرط `.Any()` باعث میشه هر mod.json معتبر و پر از محتوا، هشدار "نامعتبر است" بگیره؛
دقیقاً برعکس منطق درسته. باید هشدار فقط وقتی نشون داده بشه که RootElement آبجکت
نیست، یا وقتی هیچ property‌ای نداره ولی type مشخص نشده. لطفاً شرط رو اصلاح کن که
mod.json سالم و دارای محتوا هیچ هشداری نده.

## باگ ۲ — فقط اولین فایل سیو/DYOM نصب میشه
فایل: Forms/MainForm.cs، تابع InstallSaveOrDyomPackageAsync، انتهای حلقه‌ی
`foreach (var sourceFile in packageFiles)`
یه `break;` بدون شرط ته حلقه هست که باعث میشه فقط اولین فایل از packageFiles نصب
بشه و بقیه (اگه بسته چند تا اسلات سیو/DYOM داشته باشه) بی‌صدا نادیده گرفته بشن.
لطفاً منطق رو طوری اصلاح کن که همه‌ی فایل‌های packageFiles واقعاً نصب بشن (هرکدوم
با GetNextAvailableSlotTargetName مقصد جدا بگیره)، و به‌جای یه پیغام MessageBox
برای هر فایل (که UX بدیه)، یه پیغام خلاصه در پایان نشون بده.

## باگ ۳ — نوار پیشرفت نصب واقعی نیست
فایل: Forms/InstallProgressForm.cs، متد UpdateProgress
فایل: Forms/MainForm.cs، حدود خط 3017 (فراخوانی progressForm.UpdateProgress)
UpdateProgress فقط یه fileName می‌گیره و هر بار مقدار progress bar رو ثابت +10
اضافه می‌کنه، اما MainForm یه رشته‌ی درصد واقعی (`"42%"`) بهش پاس میده که استفاده
نمیشه. لطفاً UpdateProgress رو طوری تغییر بده که یه overload یا پارامتر جدا برای
درصد واقعی (int percent) بگیره و progressBar.Value رو دقیقاً روی همون درصد ست کنه،
و fileName جدا برای لیبل نمایش داده بشه. همه‌ی call siteها رو آپدیت کن.

## باگ ۴ — اجرای بازی برای exe فارسی کار نمی‌کنه
فایل: Services/GameService.cs
`IsValidGameFolder` هم gta_sa.exe و هم "GTA 5 FARSI.exe" رو قبول می‌کنه، اما
`LaunchGame` فقط gta_sa.exe رو هاردکد کرده (خط ~52). لطفاً LaunchGame رو طوری
اصلاح کن که همون exe معتبری که در IsValidGameFolder پیدا شده رو اجرا کنه (یه متد
مشترک برای پیدا کردن نام exe معتبر داخل پوشه بساز و هر دو متد ازش استفاده کنن).

## باگ ۵ — تشخیص وجود 7z.exe اشتباهه
فایل: Services/ModPackageService.cs، متد ExtractArchiveAsync، خط ~538
`File.Exists("7z.exe")` یه مسیر نسبیه که نسبت به working directory پروسس چک
میشه، نه پوشه‌ی نصب برنامه. لطفاً به `Path.Combine(AppContext.BaseDirectory, "7z.exe")`
تغییرش بده (و اگه 7z.exe کنار برنامه نیست، پیام خطای واضح‌تری بده که کاربر بدونه
باید 7z رو کجا بذاره).

## باگ ۶ — مسیر بکاپ جایگزین به بازی واقعی کاربر ربطی نداره
فایل: Services/BackupStorageService.cs
`ExternalBackupBase` مقدار ثابت `C:\Program Files (x86)\GTA San Andreas\zBackupFiles`
داره که کاملاً مستقل از gameFolder واقعی کاربره. لطفاً این fallback رو یا حذف کن
یا بر اساس درایو C (مثلاً `C:\GtaSaModManagerBackups`) بدون فرض کردن مسیر خاصی
از بازی بازنویسی کن.

## باگ ۷ — File.Copy با overwrite:false می‌تونه کرش کنه
فایل: Services/ModPackageService.cs، متد CopyDirectoryAsync، خط ~523
```csharp
await Task.Run(() => File.Copy(file, destination, false), cancellationToken);
```
اگه مقصد از قبل فایل هم‌نام داشته باشه IOException میده و عملیات نصب کرش می‌کنه.
لطفاً به `overwrite: true` تغییرش بده (مگر اینکه دلیل خاصی برای false بودنش پیدا
کردی که باید مستند بشه).

# بخش دوم — باگ‌ها و درخواست‌های UI/UX که کاربر خودش موقع تست پیدا کرده

## باگ ۸ — دکمه‌های Browse در Step 1/2/3 گوشه‌هاشون درست گرد نیست
فایل: Forms/MainForm.cs، متد ApplyBrowseButtonStyle (~خط 139) و CreateRoundedRectanglePath
الان از System.Windows.Forms.Button معمولی با FlatStyle.Flat استفاده شده و گردی گوشه‌ها
فقط توی رویداد Paint به‌صورت بصری کشیده میشه؛ خودِ کنترل هنوز یه مستطیل کاملاً گوشه‌تیزه.
نتیجه: حالت focus/hover سیستم‌عاملی روی گوشه‌ها به شکل تیز دیده میشه (مخصوصاً گوشه‌های
سمت راست موقع hover).
**راه‌حل درست:** یه کلاس جدید `RoundedButton : Button` بساز که:
- توی سازنده `SetStyle(ControlStyles.UserPaint | ControlStyles.AllPaintingInWmPaint | ControlStyles.OptimizedDoubleBuffer | ControlStyles.ResizeRedraw, true)` بذاره.
- `OnPaint` رو کامل override کنه (نه فقط event Paint) و علاوه بر نقاشی، `this.Region = new Region(roundedPath)` ست کنه تا شکل واقعی کنترل هم گرد بشه نه فقط ظاهرش.
- `OnGotFocus`/`OnLostFocus`/`OnMouseEnter`/`OnMouseLeave` رو override کنه و فقط رنگ پس‌زمینه/گرادینت رو عوض کنه، بدون این‌که چیزی از گردی گوشه‌ها تغییر کنه یا focus rectangle پیش‌فرض ویندوز رسم بشه (`e.Graphics` رو کنترل کن و `base.OnPaint` رو صدا نزن).
- همه‌ی call siteهای `ApplyBrowseButtonStyle` (خطوط ~542, 613, 689) رو به استفاده از این کلاس جدید تغییر بده (یا دکمه‌ها رو از اول به‌جای Button معمولی از RoundedButton بساز).

## باگ ۱۰ — دکمه Next در Step 5 باید طبق انتخاب پیش‌فرض فعال باشه
فایل: Forms/MainForm.cs، PrepareDetectedAssetStep (~خط 1400) یعنی جایی که
`_selectedAssetForInstall = sourceAsset;` ست میشه، و UpdateSidebarState (~خط 3650)

## باگ ۱۵ — عکس Step4 زیر متن «مود شناسایی شد» میره
فایل: Forms/MainForm.cs، UpdateSidebarState (~خط 3554-3623)
الان `_sidebarReadmeTextBox` با ارتفاع ثابت (150/120px) و `_sidebarStep4Image` با

واقعاً چقدر فضا لازم دارن یا کدوم‌شون اصلاً وجود داره. این باعث میشه عکس بره زیر

که این قوانین رو رعایت کنه:

### طرح‌بندی مطلوب سایدبار (زیر Input انتخاب مد):
- **اگه هم عکس هست هم README:** فضا به دو بخش تقسیم بشه — بخش بالا برای README
  (اگه متن طولانیه، اسکرول عمودی بخوره)، بخش پایین برای عکس(ها):
  - ۱ عکس → طبق جهت LTR/RTL، گوشه‌ی راست یا چپ بذارش.
  - ۲ عکس → هردو نرمال کنار هم نشون بده.
  - بیشتر از ۲ عکس → دو دکمه Next/Prev (با آیکون) کنار عکس برای گشتن بین عکس‌ها.
- **اگه فقط README هست:** تمام فضای موجود (تا انتهای ارتفاع پنجره از زیر Input)
  به README اختصاص پیدا کنه.
- **اگه فقط عکس هست:** به‌جای ۲ تا، تا ۴ تا عکس هم‌زمان نشون داده بشه:
  - ۱ عکس → طبق RTL/LTR سمت راست یا چپ.
  - ۲ عکس → هر دو بالای هم/کنار هم نشون داده بشن.
  - ۳ عکس → عکس سوم طبق RTL/LTR سمت راست یا چپ چیده بشه.
  - ۴ عکس → بدون دکمه، هر ۴ تا هم‌زمان نشون داده بشن.
  - بیشتر از ۴ عکس → دکمه‌های Next/Prev اضافه بشه.
  - ارتفاع کامل از زیر Input تا انتهای پنجره استفاده بشه، پدینگ‌ها رعایت بشه.
- اگه README طولانی بود و توی ارتفاع نمایشی جا نشد، یه فانکشن اضافه کن که تخمین
  بزنه متن چقدر ارتفاع لازم داره (بر اساس تعداد خط و فونت)، و اگه بیشتر از فضای
  موجود بود، به‌صورت خودکار Scrollbar عمودی روی TextBox/کنترل README فعال بشه.
